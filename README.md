# 標案施工現場照系統

**線上使用：<https://yuan-5149.github.io/tender-photo/>**（手機開啟後可「加入主畫面」，離線亦可拍照歸檔）

現場拍照 → 依「位置區域／工項／施工階段」歸檔 → 一鍵產出 **Word(.docx)、PDF、ZIP**。

版面完全對照既有的施工照範本（`114.08.28-龍山國中-施工照.docx`）：A4 直式、每頁一張表格、
2 欄 × 3 組（標題列＋照片列），頁首四行固定重複。

參考 [YUAN-5149/fire-photo](https://github.com/YUAN-5149/fire-photo) 的架構理念：
純前端單頁、函式庫本機打包、資料全部留在裝置上、可離線使用、GitHub Pages 直接部署。

## 功能

### 1. 專案設定（頁首四行）
| 欄位 | 對應 Word 頁首 | 格式 |
|---|---|---|
| 機關／學校名稱 | 第 1 行 | 標楷體 26pt、粗體、底線、置中 |
| 工程名稱 ＋ 文件標題 | 第 2 行 | 標楷體 16pt / 15pt、置中 |
| 工程期限（起～訖） | 第 3 行 | 標楷體 12pt、靠左 |
| 施工廠商 | 第 4 行 | 標楷體 12pt、靠左 |

多專案並存，可隨時切換；資料存在瀏覽器 IndexedDB，不上傳任何伺服器。

**日期欄位可直接鍵入**（工程期限起訖、指定日期皆同）。輸入格式自動辨識，
離開欄位或按 Enter 後統一正規化為民國格式 `115.06.01`，內部一律存 ISO：

| 可接受的輸入 | 說明 |
|---|---|
| `115.6.1`、`115/6/1`、`115-6-1` | 民國，分隔符不拘 |
| `115年6月1日`、`民國115年6月1日` | 含中文年月日 |
| `1150601` | 民國 7 碼連續數字 |
| `2026/6/1`、`2026-06-01`、`20260601` | 西元（4 碼年自動辨識） |
| `6/1` | 只給月日 → 補當年 |
| `１１５．６．１` | 全形數字與符號 |

年份小於 1000 一律視為民國。不合法的日期（13 月、2/30、非閏年的 2/29）
欄位轉紅並保留原輸入待修正，不會寫入錯誤資料。旁邊的 📅 可開系統日曆，
兩種輸入方式並存；手機上因設 `inputmode="numeric"` 會直接跳數字鍵盤。

### 2. 工項與位置區域
- **位置區域**：例「3F 301 教室」，按「＋ 新增一列」逐筆建立。
- **工項**：每個工項可設定階段組合 —
  施工前／中／後、修改前／中／後、拆除前／中／後、不分階段。
- **照片完成度**：每個工項最右側顯示狀態徽章，隨拍照即時更新 —
  - **● 已完成**（綠）：每個階段都至少有一張；不分階段的工項只要有照片即算完成
  - **◐ 尚未完整**（琥珀）：有照片但仍有階段是空的，徽章顯示 `1/3`，滑過可看缺哪幾個階段
  - **○ 無照片**（灰）：一張都還沒拍
  清單上方另有圖示說明與各狀態的項數，一眼看出還有幾項沒拍完。
- **序號與統計**：每列前方標序號，標題旁顯示「共 N 項／N 區」，一眼看得出建了幾筆。
  序號用 CSS counter 依 DOM 順序自動編，拖曳過程中就即時重編，不必等放手。
- **「＋ 新增一列」與「⇅ 手動拖移」標題旁與清單下方各一組**，兩組同步。
  從標題旁新增時會自動捲到新列並聚焦。下方那組採 `position:sticky`，捲動時會浮在
  該卡片可視範圍的右下角（讓開底部導覽列），捲出這張卡片就自動歸位——
  用 sticky 而非 fixed，浮動範圍天然限縮在自己的卡片內，兩張卡片不會同時浮出來打架。
- **鎖定／編輯兩種狀態**：預設鎖定，清單只顯示序號與名稱（工項另含階段），
  不會誤刪也不會被拖亂。按「⇅ 手動拖移」解鎖後，每列出現右側握把與 ↑↓、刪除；
  按「🔒 鎖定」回到固定狀態。
  - 拖移：抓住握把拖到任意位置，手指停在畫面上下緣會自動捲動（21 項的範本也拖得動）
  - ↑↓：單格微調；刪除：該工項若已有照片會先確認，刪除後照片變為未分類
  - 順序會反映在拍照頁的晶片、Word 分頁與 ZIP 資料夾
- **工項範本**：內建三組一鍵載入
  - 電源改善工程（教室線路更新）— 21 項，取自來源範本
  - 一般土建修繕工程 — 10 項
  - 冷氣空調工程 — 10 項

### 3. 現場拍照
- 頂端「白板」即時顯示**機關名稱／目前工項／日期**，拍照前先確認再按快門。
- 點選晶片切換 區域 → 工項 → 階段，之後每張照片自動帶入分類。
- `📷 現場拍照` 直接開手機相機；`🖼️ 從相簿匯入` 支援多選。
- 自動處理：
  - 依 EXIF 方向轉正
  - 縮至 1200／1600／2000／2600px（預設 1600）、JPEG 品質 0.82
  - 右下角燒入日期（西元或民國），可關閉
  - 日期浮水印三選一，拍照頁的晶片可隨時切換：
    - **EXIF 拍攝時間** — 依每張照片的 `DateTimeOriginal`，無 EXIF 時採檔案時間
    - **指定日期** — 全部蓋同一天，設定後持續套用
    - **不需日期** — 純圖片，右下角日期與左下角工項都不燒上去。仍會依 EXIF 轉正、
      縮到設定的解析度；拍攝日期照常記錄，ZIP 檔名與 CSV 仍看得到
  - 左下角加註工項預設關閉：該文字在匯入當下即燒進圖片，事後改分類不會跟著改，
    會與 Word 標題列不一致；Word 標題列已載明工項與階段
  - 浮水印設定在按下快門當下即快照，處理途中改設定不會讓同一批照片有的有蓋有的沒蓋；
    相簿單張編輯會標示「未加浮水印」，事後看得出這張當初是用哪種模式匯入的
- 相簿可單張編輯（改區域／工項／階段／備註、刪除），或多選批次套用分類。

### 4. 匯出
| 格式 | 產生方式 | 說明 |
|---|---|---|
| **Word (.docx)** | docx 9.7.1（本機打包） | 可直接編輯，版面與範本一致 |
| **PDF** | 瀏覽器列印 → 另存為 PDF | 中文字型完整，無需額外字型檔 |
| **ZIP** | JSZip 3.10.1 | 原始照片＋`照片清單.csv`＋`專案資訊.txt`（可含 Word 檔） |

**版面配置**四選一：
- **每欄一工項**（預設，同範本）：一個直欄放一個工項，三列由上而下為施工前／中／後，
  兩欄併成一頁 → **一頁 2 個工項**。某階段有多張照片時，該工項會再多佔一欄
- 每欄一工項，且不同區域不併頁
- 每頁一工項：同工項左右各一張，一頁 6 張
- 依序流水（每格自帶標題）

ZIP 資料夾結構可選 `工項/階段`、`區域/工項/階段` 或不分資料夾，
檔名格式為 `001_區域_工項_階段_20250828.jpg`。

> **匯出 PDF 提示**：列印對話框中，目的地選「另存為 PDF」、邊界選「無」、勾選「背景圖形」。

### 5. 安裝與離線（PWA）
- **安裝到主畫面**：Android／桌面 Chrome 會在「專案」頁出現「安裝到主畫面」按鈕；
  iOS Safari 沒有安裝 API，改顯示「分享 → 加入主畫面」的三步驟說明。已安裝時不再顯示。
- **主畫面長按捷徑**：可直接跳到「現場拍照」或「預覽與匯出」（`?view=shoot` / `?view=export`）。
- **持久化儲存**：載入時向瀏覽器申請 `storage.persist()`，避免空間吃緊時 IndexedDB 內的照片被自動清除；
  「專案清單」下方會顯示已用容量與是否取得持久保存。
- **離線指示**：斷線時頂列出現「離線中」標記，拍照與歸檔照常運作。
- **安裝對話框大圖版面**：manifest 附 5 張 `screenshots`（3 張直式 780×1560 ＋ 2 張橫式 1280×800），
  Android Chrome 會改用較豐富的安裝畫面。截圖不放進 Service Worker 快取——只有安裝對話框會用到，
  沒必要為此多佔約 1 MB 離線空間。
- **弱網保護**：Service Worker 仍是 network-first，但網路 3.5 秒沒回應就先用快取回應
  （工地常見「有訊號但極慢」比完全沒訊號更難用）；新版本仍會在背景取回並寫入快取。

### 6. 響應式版面（RWD）
| 情境 | 調整 |
|---|---|
| 窄機（≤360px） | 日期等並排欄位自動改一欄 |
| 觸控裝置 | 晶片／按鈕加大到約 44px，戴手套也點得到 |
| 手機橫放 | 白板壓縮、底部導覽列改為橫向小列，讓出垂直空間 |
| 平板（≥760px） | 導覽列改 sticky、相簿格放大 |
| 桌機（≥1080px） | 專案／工項／匯出頁改雙欄，版面預覽跨欄 |
| A4 預覽 | 依容器寬度即時換算縮放比，任何螢幕都剛好塞滿、不橫向捲動 |

另支援 `prefers-reduced-motion`，並以 `env(safe-area-inset-*)` 避開瀏海與圓角（含橫向時的左右）。

## 使用方式

### 本機執行
需要以 HTTP 提供（Service Worker 與 IndexedDB 在 `file://` 下受限）：

```bash
python -m http.server 8931
```

瀏覽 <http://localhost:8931>。

### 部署

已部署於 GitHub Pages（`main` 分支根目錄）：<https://yuan-5149.github.io/tender-photo/>

純靜態、無建置流程，`vendor/` 內已含所有函式庫，不依賴 CDN。改好推上 `main` 即自動重新部署：

```bash
git add -A && git commit -m "說明" && git push
```

Service Worker 採 network-first，使用者重新整理即取得新版，不需清快取。
改動 `sw.js` 內 `ASSETS` 清單時記得同步調高 `CACHE` 版本號（目前 `tender-photo-v3`）。

介面大改後，安裝對話框的截圖要重拍（先開好 `python -m http.server 8931`）：

```bash
node tools/make-screenshots.mjs "C:\Program Files (x86)\Google\Chrome\Application\chrome.exe" http://localhost:8931 screenshots
```

腳本會在暫存 profile 裡塞示範資料再截圖，不會動到你瀏覽器裡的實際專案。

## 檔案結構

```
tender-photo/
├── index.html            介面骨架
├── assets/app.css        樣式 ＋ A4 列印版面
├── js/
│   ├── util.js           日期（民國/西元）、檔名、DOM 工具
│   ├── store.js          IndexedDB 專案與照片存取、階段組合定義
│   ├── presets.js        工項範本庫
│   ├── imaging.js        EXIF 日期解析、壓縮、浮水印
│   ├── layout.js         版面配置演算法（三種輸出共用）
│   ├── export-docx.js    Word 產生（對齊範本量測值）
│   ├── export-print.js   A4 預覽與列印 PDF
│   ├── export-zip.js     ZIP 打包與 CSV 清單
│   └── app.js            畫面與流程控制
├── tools/
│   └── make-screenshots.mjs  重新產生 manifest screenshots（CDP，無需安裝套件）
├── vendor/               docx 9.7.1、JSZip 3.10.1（本機打包）
├── icons/                PWA 圖示（any／maskable／apple-touch-icon）
├── screenshots/          安裝對話框用截圖（直式 ×3、橫式 ×2）
├── manifest.json         含 id、display_override、shortcuts、screenshots
└── sw.js                 Service Worker（network-first ＋ 弱網逾時回退快取）
```

## 後續可調整方向

- 每頁欄數／列數改為可設定（目前固定 2 × 3）
- 左右兩欄可設不同工項（範本中部分頁面如此）
- 頁尾頁碼、簽核欄位
- 照片旋轉／裁切工具
- 匯出設定檔，於多台裝置間同步工項清單
- 深色模式（現場多在戶外強光下，暫以淺色為主）
- 截圖目前是以示範資料重拍的；介面大改後需重新產生（見下）
